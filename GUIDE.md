## 1. Что это за приложение

Это внутренний сайт-ассистент, который отвечает сотрудникам на вопросы по регламентам компании (охрана труда, техника безопасности, отпуска, инструктажи и т.д.), используя подход **RAG** (Retrieval-Augmented Generation): ответ не выдумывается моделью «из головы», а генерируется на основе реально найденных фрагментов загруженных документов.

Всё работает **полностью локально**, без обращения к внешним API (OpenAI и т.п.) — и языковые модели, и векторный поиск развёрнуты на самом сервере. Это важно, если регламенты содержат внутреннюю информацию компании, которую нежелательно отправлять наружу.

### Как обрабатывается один вопрос

```
Вопрос сотрудника (+ история последних вопросов в этом диалоге)
      │
      ▼
0. Анализ истории — если вопрос короткий/обрывочный ("Где взять") и
   зависит от темы предыдущих 2–3 вопросов ("...работа на высоте"),
   LLM переписывает его в самостоятельный: "Где взять экипировку
   для работы на высоте?". Явные приветствия и уже самодостаточные
   вопросы пропускают этот шаг — лишний вызов модели не тратится.
      │
      ▼
1. Классификация (быстрый префильтр + LLM):
   "general" (приветствие) / "rag" (вопрос по регламентам) / "escalate" (травма, конфликт)
      │
      ▼  (если route = rag)
2. Векторный поиск в Qdrant — находим 3 ближайших по смыслу фрагмента
      │
      ▼
3. Реранжирование — LLM оценивает, насколько каждый фрагмент
   реально отвечает на вопрос (0.0–1.0)
      │
      ▼
4. Confidence gate — если релевантность ниже порога (0.55),
   ответ не генерируется (честное "не знаю" вместо галлюцинации)
      │
      ▼
5. Генерация ответа большой моделью на основе отобранных фрагментов
```

История диалога хранится в памяти процесса сайта, по `session_id` (своя история на каждую открытую вкладку браузера, сбрасывается при обновлении страницы или по кнопке «Новый диалог»). Учитываются только последние 3 вопроса — этого достаточно, чтобы разрешить продолжение темы, и не даёт старым, уже неактуальным вопросам влиять на новые.

### Как документ попадает в систему

```
Загрузка (сайт) или файл в data/documents
      │
      ▼
docling — разбор структуры PDF/DOCX (заголовки, разделы, таблицы, страницы)
      │
      ▼
Смысловой чанкинг (HybridChunker) — куски по разделам,
а не механически по количеству символов
      │
      ▼
Эмбеддинг каждого чанка (модель bge-m3) → вектор
      │
      ▼
Запись в Qdrant — готово к поиску за миллисекунды
```

## 2. Из чего оно состоит

### Компоненты (сервисы)

| Компонент | Роль | Порт | Как запущен |
|---|---|---|---|
| **Сайт (FastAPI)** | Веб-интерфейс + API (`/ask`, `/documents`) | 8000 | systemd: `rag-app` |
| **Qdrant** | Векторная база данных для поиска фрагментов | 6333/6334 (только localhost) | Docker-контейнер |
| **Ollama** | Локальный сервер LLM-моделей | 8080 (только localhost) | systemd: `ollama` |

### Модели внутри Ollama

| Модель | Зачем нужна |
|---|---|
| `bge-m3` | Превращает текст (вопрос и чанки документов) в векторы для поиска |
| `qwen2.5:3b` | Быстрая модель: классификация вопроса и реранжирование фрагментов |
| `qwen3:14b` | Модель побольше: генерация финального ответа сотруднику |

### Файлы проекта

| Файл / папка | Назначение |
|---|---|
| `app.py` | FastAPI-приложение: отдаёт сайт, эндпоинты `/ask`, `/documents` (список/загрузка/удаление), `/session/{id}` (сброс истории); хранит историю диалогов по `session_id` в памяти процесса |
| `indexing.py` | Вся логика обработки документов: docling → чанкинг → эмбеддинги → Qdrant, реестр документов |
| `index_documents.py` | CLI-скрипт для разовой пакетной индексации папки `data/documents` |
| `rag.py` | RAG-пайплайн: анализ истории → классификация → поиск → реранк → генерация ответа |
| `static/index.html` | Фронтенд: панель загрузки документов + чат с ассистентом |
| `install.sh` | Установка всех зависимостей и настройка сервера (см. раздел 4) |
| `requirements.txt` | Python-зависимости |
| `data/documents/` | Оригиналы загруженных регламентов (pdf, docx, ...) |
| `data/processed/` | Кэш разобранных docling документов (JSON) — ускоряет повторную обработку |
| `data/registry.json` | Реестр: какой файл когда загружен, статус индексации, число чанков |

## 3. Требования и подготовка сервера

### Минимальные характеристики сервера

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu 22.04 / 24.04 LTS (или другой Debian-based) | Ubuntu 24.04 LTS |
| CPU | 4 ядра | 8 ядер (без GPU разбор PDF и генерация ответа идут на CPU) |
| RAM | 16 ГБ | 32 ГБ |
| Диск | 30 ГБ свободно | 60+ ГБ (веса моделей + база Qdrant растут со временем) |
| GPU | не обязателен | NVIDIA с CUDA — сильно ускоряет и docling, и Ollama |
| Сеть | исходящий доступ в интернет на время установки (apt, docker, ollama, pip) | — |

Модель `qwen3:14b` без GPU занимает ~9+ ГБ оперативной памяти сама по себе — это и определяет минимум по RAM.

### Чек-лист перед установкой

1. **Доступ по SSH** с правами root или пользователя с sudo.
2. **Обновить систему:**
   ```bash
   sudo apt-get update && sudo apt-get upgrade -y
   ```
3. **Проверить часовой пояс** (важно для читаемых меток времени в реестре документов и логах):
   ```bash
   timedatectl set-timezone Europe/Moscow   # подставьте свой пояс
   ```
4. **Убедиться, что порт 8000 свободен** (или решить, на каком порту будет сайт).
5. Если сервер за корпоративным firewall — заранее согласовать открытие исходящих соединений к `github.com`, `ollama.com`, Docker Hub и репозиториям `apt` (нужны на этапе установки).
6. (Опционально, для продакшена) — домен, направленный на IP сервера, и обратный прокси с TLS — см. раздел 10.

Дальше всю установку берёт на себя `install.sh` — apt-пакеты, Python-окружение, Docker, Qdrant, Ollama и systemd-сервисы настраиваются им автоматически.

## 4. Развёртывание с нуля

```bash
# 1. Скопировать проект на сервер (пример через scp; можно и через git clone)
scp -r project/ user@server:/opt/rag-assistant
ssh user@server

# 2. Перейти в папку проекта
cd /opt/rag-assistant

# 3. Запустить установку
chmod +x install.sh
./install.sh
```

`install.sh` выполняет:
- системные apt-пакеты;
- виртуальное окружение `.venv` + `pip install -r requirements.txt`;
- Docker + контейнер Qdrant (`--restart unless-stopped`, порты только на `127.0.0.1`);
- Ollama как systemd-сервис на порту 8080 + загрузку моделей `bge-m3`, `qwen2.5:3b`, `qwen3:14b`;
- systemd-сервис `rag-app` для самого сайта.

В конце скрипт сам проверяет, что Qdrant и Ollama отвечают, и печатает команды для запуска сайта.

**После установки — проиндексируйте стартовый набор документов** (если они уже лежат в `data/documents`, включая два тестовых регламента):

```bash
source .venv/bin/activate
python index_documents.py
```

Затем запустите сайт (см. раздел 5).

## 5. Как запускать в дальнейшем

Сайт и Ollama работают как systemd-сервисы — управляются стандартными командами, `install.sh` запускать повторно не нужно.

### Запуск / остановка / перезапуск сайта

```bash
sudo systemctl start rag-app      # запустить
sudo systemctl stop rag-app       # остановить
sudo systemctl restart rag-app    # перезапустить (например, после обновления кода)
sudo systemctl status rag-app     # проверить, что запущен и без ошибок
```

### Автозапуск при перезагрузке сервера

Уже включён при установке (`systemctl enable rag-app` внутри `install.sh`). Проверить:
```bash
systemctl is-enabled rag-app   # должно вывести "enabled"
```

### Логи

```bash
sudo journalctl -u rag-app -f       # логи сайта в реальном времени
sudo journalctl -u ollama -f        # логи Ollama
sudo docker logs -f qdrant          # логи Qdrant
```

### Проверка, что всё живо (health check)

```bash
curl -s http://127.0.0.1:6333/collections   # Qdrant
curl -s http://127.0.0.1:8080/api/tags      # Ollama — список загруженных моделей
curl -s http://127.0.0.1:8000/documents     # сайт — список документов
```

### Управление сопутствующими сервисами

```bash
sudo systemctl restart ollama         # перезапустить Ollama
sudo docker restart qdrant            # перезапустить Qdrant
sudo docker stop qdrant / start qdrant
```

## 6. Работа с документами

### Через сайт (обычный способ)

Открыть `http://<адрес-сервера>:8000`, перетащить PDF/DOCX в область загрузки. Файл сразу проходит через docling и становится доступен для поиска — статус на странице обновляется автоматически.

### Через папку на сервере (пакетно, много файлов сразу)

```bash
cp новый_регламент.pdf /opt/rag-assistant/data/documents/
cd /opt/rag-assistant
source .venv/bin/activate
python index_documents.py
```

### Удаление документа

Через сайт — кнопка «Удалить» у документа. Либо напрямую:
```bash
curl -X DELETE http://127.0.0.1:8000/documents/имя_файла.pdf
```

### Полная переиндексация с нуля

Если нужно пересобрать всю коллекцию Qdrant заново (например, поменяли параметры чанкинга в `indexing.py`):
```bash
python index_documents.py --recreate
```

## 7. Резервное копирование

Что нужно бэкапить регулярно:

| Что | Где лежит | Зачем |
|---|---|---|
| Оригиналы документов | `data/documents/` | Без них нельзя переиндексировать при потере Qdrant |
| Реестр документов | `data/registry.json` | Статусы и метаданные загрузок |
| Хранилище Qdrant | `./qdrant_storage/` (volume контейнера) | Сами векторы — самое дорогое по времени пересчёта |

Пример простого бэкапа в архив:
```bash
tar -czf backup_$(date +%F).tar.gz data/ qdrant_storage/
```

Восстановление — распаковать архив на новом сервере в ту же структуру папок и запустить контейнер Qdrant с тем же volume; переиндексация не потребуется, если восстановлен `qdrant_storage`.

## 8. Обновление кода

```bash
cd /opt/rag-assistant
git pull                      # или скопировать новые файлы вручную
source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
sudo systemctl restart rag-app
```

Если менялась только логика чанкинга/эмбеддингов — после обновления кода имеет смысл `python index_documents.py --recreate`, чтобы переиндексировать документы новым способом.

## 9. Диагностика проблем

| Симптом | Вероятная причина | Что проверить |
|---|---|---|
| Сайт не открывается | `rag-app` не запущен | `sudo systemctl status rag-app`, `journalctl -u rag-app -e` |
| Ответы всегда "не знаю" | Порог confidence не пройден / документы не проиндексированы | `curl http://127.0.0.1:8000/documents` — есть ли документы со статусом `indexed` |
| Ошибка подключения к Ollama | Ollama слушает не на 8080 | `sudo systemctl cat ollama` — проверить, что применился override `OLLAMA_HOST=127.0.0.1:8080` |
| Сервер завис / OOM при генерации | Не хватает RAM под `qwen3:14b` | `free -h`, рассмотреть модель поменьше в `rag.py` (`BIG_MODEL`) |
| Загрузка документа зависает надолго | Первый разбор PDF (docling) идёт на CPU и без кэша | Проверить `data/processed/` — появился ли кэш; повторная обработка того же файла будет быстрее |
| `docker: permission denied` | Пользователь не в группе `docker` | Перелогиниться после установки, либо запускать команды с `sudo` |

## 10. Безопасность

- Qdrant (6333) и Ollama (8080) намеренно привязаны только к `127.0.0.1` — не открывайте эти порты в firewall наружу.
- Наружу нужен только порт сайта (8000). Для продакшена рекомендуется не пробрасывать 8000 напрямую в интернет, а поставить перед ним обратный прокси (nginx / Caddy) с TLS-сертификатом (Let's Encrypt) и, при необходимости, базовой аутентификацией — сейчас сайт сам по себе не проверяет, кто задаёт вопросы.
- Регламенты компании могут быть внутренним документом — ограничьте доступ к серверу и к самому сайту кругом сотрудников, для которых он предназначен (VPN, аутентификация на уровне прокси, ограничение по IP).
- Регулярно обновляйте систему (`apt-get upgrade`) и образы (`docker pull qdrant/qdrant`, обновления Ollama) — это не входит в `install.sh` и делается вручную по мере необходимости.
